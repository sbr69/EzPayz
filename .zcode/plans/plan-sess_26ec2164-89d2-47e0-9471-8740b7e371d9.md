# Marketplace ↔ EzPayz Integration — Human Checkout + x402 Agent, Chat Fixed

## Context
The "Sill & Shelf" marketplace (`EzPayz/marketplace/`, Next.js on `:3000`) already implements both flows in code — human hosted-checkout (`orders` routes → `src/lib/server/gateway.ts` → EzPayz `POST /v1/payment-intents` → `/real-checkout/<slug>`) and the x402 agent flow (shopping chat + developer lab → facilitator `/v1/x402/verify|settle`). They're disconnected purely by configuration: `EZPAYZ_SECRET_KEY`, `EZPAYZ_WEBHOOK_SECRET`, `EZPAYZ_PAYOUT_WALLET`, `X402_AGENT_PRIVATE_KEY` are empty, `APP_ORIGIN` points at a dead port (3016 vs the running dev server on 3000), and the chat's "Live catalog is unavailable" is the shop route 503ing when `DATABASE_URL` isn't loaded by the running server (the AI itself is real — Groq `openai/gpt-oss-20b`, key configured).

All missing values can be produced programmatically. Goal: a smooth, working integration for both purchase modes, verified live.

## Part A — Fill `marketplace/.env` with real values (no manual steps for the owner)
1. **`EZPAYZ_SECRET_KEY`** — create a dedicated API key for the marketplace via `POST /v1/api-keys` (merchant JWT from the browser session, name "Sill & Shelf marketplace") → capture the shown-once secret → write into `marketplace/.env` without printing it.
2. **`EZPAYZ_PAYOUT_WALLET`** — fetch via `GET /v1/merchants/me` (the verified payout wallet of Local Test Merchant) → write it.
3. **`EZPAYZ_WEBHOOK_SECRET`** — create the webhook endpoint via `POST /v1/webhooks` (`url: http://localhost:3000/api/webhooks/ezpayz`, eventTypes: payment.succeeded/failed/refund.succeeded) → capture the returned `signingSecret` → write it. (The local API can deliver to localhost:3000 — same machine.)
4. **`X402_AGENT_PRIVATE_KEY`** — the funded agent wallet from the gateway root `.env` (`TEST_PAYER_PRIVATE_KEY`, holds test USDT, differs from the payout wallet as required).
5. **Origins** — `APP_ORIGIN=http://localhost:3000`, `EZPAYZ_API_URL=http://localhost:4000` (instant, local), `EZPAYZ_CHECKOUT_ORIGIN=http://localhost:5173` (hosted checkout on the local web app). Keep `GROQ_API_KEY`, `GROQ_MODEL=openai/gpt-oss-20b`, `X402_OPERATOR_TOKEN`, `DATABASE_URL` as-is.
6. **Create `.env.example`** (missing, but referenced by README/.gitignore) with all 11 vars documented.

## Part B — Database + restart
- `npm run db:migrate` (applies `0002-x402-agent.sql` — the agent runs/budget tables) + `npm run db:seed` if products are missing.
- Restart the marketplace dev server so Next.js picks up the env (its catalog banner should disappear).

## Part C — Live verification (both flows)
1. **AI model check**: one real Groq chat-completion call with the configured key/model → confirm `openai/gpt-oss-20b` responds; if dead, switch `GROQ_MODEL` to an active Groq model (`llama-3.3-70b-versatile`).
2. **x402 catalog resource**: `GET /api/x402/catalog` → expect HTTP 402 with `X-PAYMENT-REQUIREMENTS` (proves APP_ORIGIN + payout wallet wiring).
3. **Shop chat backend**: `POST /api/x402/shop {action:"search"}` → expect real Groq suggestions from the live catalog (kills "Live Catalog Unavailable").
4. **Quote endpoint**: `POST /api/x402/shop {action:"quote"}` → expect HTTP 402 + a 5-minute payment quote.
5. **Human checkout**: `POST /api/orders` with a cart → expect `{checkoutUrl}` pointing at `http://localhost:5173/real-checkout/<slug>`; `GET /v1/checkout/<slug>` confirms the intent exists with the order's amount.
6. **Webhook delivery**: fire a test event from the gateway to `http://localhost:3000/api/webhooks/ezpayz`-style dispatch (or verify the signature path with curl) — expect signature verification to pass.
7. Then the owner does the browser parts that need a human: pay the hosted checkout with MetaMask, and click through the chat purchase (quote → sign → settle).
